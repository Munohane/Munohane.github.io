Gestion Association

Plateforme web complète pour l'administration bénévole

À propos du projet

Développement d'une solution web centralisée pour faciliter l'organisation interne d'une association. Le site remplace les fichiers Excel disparates par une base de données robuste et accessible partout pour les gérants et les bénévoles.

Fonctionnalités Clés

Système d'authentification sécurisé : Rôles distincts (Administrateur, Gérant, Bénévole) avec des permissions spécifiques pour chaque type de profil.

Gestion des événements : Création, modification et suppression d'événements (CRUD) avec gestion des inscriptions en temps réel par les gérants.

Base de données : Modélisation complexe des relations entre adhérents, événements et inscriptions via CakePHP.

Zoom Technique

Architecture MVC avec CakePHP

Le projet suit strictement le pattern MVC (Modèle-Vue-Contrôleur) imposé par CakePHP. Chaque entité (Adhérent, Événement, Inscription) possède son propre modèle avec ses règles de validation, son contrôleur pour la logique métier, et ses vues Twig. Les relations entre tables sont déclarées via les associations CakePHP (hasMany, belongsToMany), ce qui permet de charger les données liées en une seule requête grâce au lazy loading.

Extrait — Gestion des rôles et permissions (PHP)

// Dans AppController.php — vérification du rôle avant chaque action
public function beforeFilter(EventInterface $event): void
{
    parent::beforeFilter($event);
    $user = $this->Authentication->getIdentity();

    // Seuls les admins et gérants peuvent accéder aux actions CRUD
    $restrictedActions = ['add', 'edit', 'delete'];
    if (in_array($this->request->getParam('action'), $restrictedActions)) {
        if (!$user || !in_array($user->role, ['admin', 'gerant'])) {
            $this->Flash->error('Accès refusé.');
            return $this->redirect(['action' => 'index']);
        }
    }
}

Modélisation de la base de données

La relation N:N entre Adhérents et Événements est gérée via une table de jointure inscriptions qui stocke également des métadonnées (date d'inscription, statut de présence). Cette approche évite la duplication de données et permet des requêtes agrégées efficaces pour les tableaux de bord administrateur.

TCGP GO LITE

Application mobile Android de collection gamifiée

À propos du projet

Création d'une application mobile Android native développée en Kotlin. L'objectif est d'offrir une expérience de collection addictive où l'utilisateur récolte des Pokémon, gère son inventaire et accomplit diverses missions pour progresser. Ce projet implique à la fois le développement frontend mobile et la création d'une architecture backend sur mesure.

Fonctionnalités Clés

Ouverture de Boosters : Implémentation d'une mécanique de récompense sous forme de boosters de cartes virtuels. Les boosters se rechargent au fil du temps, incitant l'utilisateur à revenir régulièrement.

Système de Missions : Intégration de quêtes et missions interactives qui guident le joueur et lui permettent de débloquer du contenu exclusif ou des boosters supplémentaires.

Création d'API REST : Conception et déploiement d'une API personnalisée pour fournir à l'application toutes les données nécessaires (statistiques, images, raretés des Pokémon).

Développement Android Natif : Application entièrement conçue en Kotlin via Android Studio, respectant les bonnes pratiques et le cycle de vie Android.

Zoom Technique

Architecture : MVVM + Repository Pattern

L'application suit le pattern MVVM (Model-View-ViewModel) recommandé par Google pour Android. Chaque écran possède son ViewModel qui expose des StateFlow observés par les Composables Jetpack. La couche données est isolée via un Repository qui abstrait la source (API REST ou cache local Room), permettant de changer de source sans toucher à l'UI.

Extrait — Gestion du timer de recharge des boosters (Kotlin)

// ViewModel — calcul du temps restant avant le prochain booster
class BoosterViewModel(private val repo: BoosterRepository) : ViewModel() {

    val boosterState: StateFlow<BoosterUiState> = repo.getBoosterFlow()
        .map { booster ->
            val remaining = booster.nextOpenTime - System.currentTimeMillis()
            if (remaining <= 0) BoosterUiState.Ready
            else BoosterUiState.Cooldown(remaining)
        }
        .stateIn(viewModelScope, SharingStarted.WhileSubscribed(5000), BoosterUiState.Loading)

    fun openBooster() = viewModelScope.launch {
        repo.openBooster() // Appel API + mise à jour Room
    }
}

API REST personnalisée

Plutôt que d'utiliser directement la PokéAPI publique (trop volumineuse), une API intermédiaire a été développée et déployée pour ne retourner que les champs nécessaires à l'app (nom, image, rareté, type). Cela réduit la taille des réponses de ~90% et permet d'ajouter des données custom (probabilités de drop par rareté) non présentes dans les APIs publiques.
